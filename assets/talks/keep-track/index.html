The problem

A correct quotation can accompany a wrong claim

Drug A does not inhibit Gene B in assay X.

Suppose an extractor quotes this sentence exactly, but returns:

POSITIVE <Drug A, inhibits, Gene B>, assay = X

QuestionResult for this example
Does the quotation occur in the source?Yes. Every quoted character matches.
Does the source support the claim?No. “Does not inhibit” contradicts the positive claim.

Source support means the claim follows from the cited text. Here, we must keep NOT, Drug A as subject, Gene B as object, and assay X.

The quotation and the claim are separate outputs. Copying the evidence correctly only answers where the words came from. It does not establish that the extractor interpreted them correctly. In this example all names and the assay match, so the only error is the missing negation. Source support concerns what the supplied text says; it does not independently verify the biological statement. The checker implements this requirement for declared sentence patterns, not arbitrary natural language. Source: claim-validation study.

type Extractor = Callable[[Document], list[Claim]]

def synthesize(source: Document, policy: Policy) -> Extractor | Failure:
    feedback: Refusal | None = None
    while requests_remain(policy):
        program: Extractor = propose(source, policy.operations, feedback)
        budget: Budget = fresh_budget(policy)
        result: Accepted | Refusal = execute_and_check(program, source, policy, budget)
        if isinstance(result, Accepted):
            return program
        feedback = result
    return Failure()

def _add(
    self,
    span: Span,
    anchor: str,

    *,

def spend(self, key: str, cost: int) -> None:
    charges = {key: cost}
    if "edit" in self.policy.budgets:
        charges["edit"] = cost
    prospective = {
        category: self.spent.get(category, 0) + charge
        for category, charge in charges.items()

    for category, used in prospective.items():

        if used > limit:
            raise ValidationProblem(
                f"edit budget exceeded for {category}: {used}/{limit}",
                stage="lexical",
            )
    self.spent.update(prospective)

Coverage comes from the provenance tree

Drug A does not inhibit Gene B in assay X.

A provenance tree links a checked claim to the source words supporting it. Here, its leaves identify the subject, predicate, object, qualifier and negation cue. A token is one word: “Drug A” has two.

Coverage = (2 + 1 + 2 + 2 + 1) / 10 = 0.80

If only “assay X” is grounded as context, coverage is (2 × 0.5) / 10 = 0.10. With neither a relation nor grounded context, coverage is 0.

Conceptual view of source support used for coverage, not a claim that the evaluator recursively traverses every derivation node. The implementation reads each admitted relation proof's parsed role ranges, context mentions and negation cues, then checks grounded context values. It credits each source word once: 1 for relation-supported ranges, context_credit=0.5 for context-only ranges, otherwise 0. Only the scored document counts. The complete evidence quotation is not a coverage range. Actual coverage and token_credits implementation; PR #12.

Formalizing the interpretation

  • Typed meaning: the model builds a SentenceMeaning in Python under the restricted evaluator; every span comes from span_at.
  • Checks live with their claims: roles bind the pair by span identity, pairing yields the assignments, scope composes into one commitment.
  • The predicate is the domain's: a native keyword refined from the trigger and priced like an extractor's mapping.
  • Each relation is an entailment: sentence as premise, relation and commitment as conclusion, unchecked steps as assumptions; NO_RELATION needs a closed-world premise.

    object: SpanProof

            self.facticity,

        """The claim in words, read back from its label and its triplet's

Proposed extension: one extractor across documents

Search for a program that covers more examples

Let D = {d₁, …, dₙ} be n source documents, e.g., a positive Drug A/Gene B sentence, a negative Drug A/Gene C sentence, and “Drug A may inhibit Gene B in assay X.” Run the same P on all three.

P⋆∈ arg maxP∈PAccepted on D 1n∑i=1nC(P,di) subject to u(P,di)≤Bi,∀i

1/n ∑ averages coverage across documents. ∀i means every document has its own cap Bᵢ. Accepted on D requires all executions to pass; returning no claim on “may inhibit” remains valid.

This maximizes average word coverage. Counting correctly recovered examples is a separate evaluation using reference answers: for instance, recover both supported claims and abstain on the uncertain third sentence.

Proposed aggregate objective, not an implemented result. The existing plan keeps coverage and spending separate for each document. PR #13 currently searches for a different program per source.

Local design document: keep-track/.claude/worktrees/paper-plan/COVERAGE_OPTIMIZATION_PLAN.md, dataset-mode section. It proposes separate per-document coverage/edit objectives and retaining candidates not beaten on both, with final selection by coverage then spending. The displayed mean-coverage problem is a concrete proposed aggregation for discussion, not a claim that the plan or PRs implement it. Budgets here reset per document; there is no shared corpus-wide spending cap. The token-coverage surrogate does not certify completeness or correct abstention. Gold reference labels stay outside the search objective. No implemented dataset-mode study was found in the fetched PRs or branches as of October 19, 2026.

Maximize coverage minus edit cost

P is a proposed extractor; d is one source sentence. C(P, d) is its checked word coverage, e.g., 7/8 for our positive Drug A/Gene B sentence. u(P, d) is the cost of permitted transformations of source-derived text, e.g., an addition charged 1 unit. B > 0 is the allowance: spending 1 unit from B = 2 uses half.

P⋆∈ arg maxP∈PAccepted [C(P,d)−λu(P,d)B]

arg max selects a program with the largest score. 𝒫Accepted contains submitted programs that pass source checks and all edit limits. λ sets the cost penalty; PR #13 uses λ = 0.5.

The controlling Python program asks the model for six extractor proposals, scores each with a fresh edit budget, and selects the highest-scoring passing submission. A Refusal scores −1.5. The table is illustrative.

This search gives no global optimality guarantee. Equation summarizes final selection in run_search, introduced in PR #13. Budget B is edit_limit(policy), capped by the aggregate edit limit and the sum of per-kind limits; each candidate must also satisfy those individual limits. u is edit_spending, summed once across edit kinds. These are evidence-operation costs, not edits to Python source or model request costs. The empty seed guides proposals but is excluded from final answers. The arg max is a set, so membership allows tied winners. The numerical example assumes a richer source with an approved paid normalization that unlocks extra supported content; the ten pilot sentences do not demonstrate this tradeoff.
