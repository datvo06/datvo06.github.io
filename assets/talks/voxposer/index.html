Reconstruction: the setup

Recover the poses of two known dominoes from one saved tabletop observation.

  • Scene: two rigid dominoes on a table. Reconstruct only these objects.
  • Observation: RGB, aligned 3D points from FoundationStereo, and saved object masks.
  • Human input: one pixel per domino and a clear rectangular patch of the table.
  • Frame: fit using the table plane, then express both poses in the camera frame.

This is an offline reconstruction of a static capture. A robot controller is not running.

Source bundle exp_20260917_141030/look_01/bundle/30264679. The capture metadata identifies FoundationStereo as the XYZ source and supplies K_scaled. The selected pixels are grey (400, 340) and green (505, 390); the smallest saved masks containing them are indices 22 and 2. The clear table region is [540, 390, 680, 470]. Its measured plane RMS is 0.30 mm. The script reads saved fastsam_masks.npz and does not run segmentation again; that filename alone does not establish whether SAM2 refinement was used upstream. This run uses no camera-to-robot extrinsic transform. The recent robot-camera recalibration is therefore not applied here. Reconstruction: the workflow

  1. Select the objects. Choose each saved mask from its clicked pixel. Reuse the archived segmentation and depth.
  2. Prepare the 3D points. Measure a table-aligned frame from the clear patch. Erode object-mask boundaries and filter invalid or distant depth points.
  3. Fit known domino geometry. Try several initial poses and minimize distance to the box surface. Constrain the bottom to touch the table.
  4. Resolve the visible side. Compare thickness-shifted alternatives against the surrounding 3D cloud to choose which side of the observed face the box occupies.
  5. Export and check. Transform poses back to the camera frame, generate RoboTL, compile to MuJoCo, and compare the rendered view with the observation.

SDF means signed distance to the box surface. The fitting constraint does not weld the exported bodies to the table.

Canonical owners are BabyRobot markerless.domino_fit.mask_to_base_points, fit_domino_pose and scene.fit_dominoes.resolve_side. Mask erosion is two pixels; foreground filtering keeps camera-depth points within 0.10 m of the fifth percentile, with at most 4000 points. Contact fitting optimizes x, y and two constrained orientation angles, deriving vertical position from known geometry and table height. resolve_side compares candidates shifted by plus or minus one thickness along the box normal and requires improved full-cloud support. The runner snapshot is from commit ef07da9; canonical function source hashes are recorded in the code download. This is numerical fitting and deterministic program export, not LLM program synthesis or MPC.
